# Chat-agent framework

The operator-facing framework processes conversational turns through shared agent services, provider adapters, channel transports, and bounded tools; it is distinct from the timer-driven host runtime in [[architecture#Two runtime surfaces#Operator-facing chat framework]].

## Turn processing and conversation state

The agent assembles conversational context, invokes models and tools, and maintains session memory.

[[nanobot/agent/loop.py#AgentLoop]] coordinates a turn: context assembly, model generation, tool execution, and response delivery. [[nanobot/agent/context.py#ContextBuilder]] composes prompt material and [[nanobot/agent/memory.py#MemoryStore]] owns persisted conversational memory; [[nanobot/session/manager.py#SessionManager]] separates sessions. Prompt size and source trust boundaries remain explicit; runtime-specific policy imported by shared context does not make the chat framework a host-cycle authority. Existing checks include [[tests/test_memory_v2.py#test_interactive_context_keeps_legacy_memory]], [[tests/test_session_manager.py#test_session_manager_repairs_corrupt_jsonl]], and [[tests/test_context_prompt_budget.py#test_oversized_bootstrap_preserves_memory_and_skills_and_reports_drop]]. CLI interaction tests are in [[tests/test_cli_input.py#test_read_interactive_input_async_returns_input]].

## Tools, skills, and delegated work

Registered tools provide bounded interfaces for agent side effects, skills, and delegated work.

[[nanobot/agent/tools/registry.py#ToolRegistry]] provides the tool contract; individual adapters cover filesystem, shell, web, messaging, cron, memory search, MCP, and spawn. Tools expose side effects through their own boundaries: filesystem paths are constrained, shell execution is bounded, and web targets are validated. [[nanobot/agent/skills.py#SkillsLoader]] loads skill guidance; bundled skill-creator scripts validate/package authored skills, while tmux scripts are executable helpers rather than Python APIs. Verification includes [[tests/test_tool_validation.py#test_registry_returns_validation_error]], filesystem restriction checks in [[tests/test_filesystem_tools.py#TestWorkspaceRestriction]], bounded shell output in [[tests/test_exec_security.py#test_exec_streams_output_in_bounded_reads]], and web safety in [[tests/test_web_fetch_security.py#test_web_fetch_blocks_private_ip]]. MCP cancellation is checked by [[tests/test_mcp_tool.py#test_execute_re_raises_external_cancellation]]; delegated tool registration by [[tests/test_subagent_manager.py#test_executor_declared_and_registered_tool_names_match]]; skill assets by [[tests/test_skill_creator_scripts.py#test_validate_skill_accepts_existing_skill_creator]].

## Channels and message transport

The bus and channel adapters define the chat message transport boundary.

[[nanobot/bus/queue.py#MessageBus]] transports typed [[nanobot/bus/events.py#InboundMessage]] and [[nanobot/bus/events.py#OutboundMessage]] values between [[nanobot/channels/manager.py#ChannelManager]] and the agent-facing path. [[nanobot/channels/base.py#BaseChannel]] defines lifecycle behavior; channel discovery and Telegram are adapters, not a guarantee that every channel is configured or running. Existing checks include exact sender matching in [[tests/test_base_channel.py#test_is_allowed_requires_exact_match]], plugin discovery in [[tests/test_channel_plugins.py#test_discover_all_includes_builtins]], and Telegram group policy in [[tests/test_telegram_channel.py#test_telegram_group_policy_defaults_to_mention]]. Message-bus edge cases without a named assertion are unknown here.

## Configuration, CLI, and package contracts

Typed configuration and dual CLI entry points define operator-facing package contracts.

[[nanobot/config/schema.py#Config]] is the typed configuration contract and [[nanobot/config/loader.py#load_config]] loads/migrates it; [[nanobot/config/paths.py#get_data_dir]] resolves user data paths. The supported `nanobot` CLI and external `eeebot` compatibility CLI remain separate entry points: [[nanobot/cli/commands.py#main]] and [[nanobot/cli/eeebot.py#main]]. Interactive configuration, model discovery, and gateway commands are operator surfaces, not host deployment controls. Existing checks cover typed defaults in [[tests/test_config_schema.py#test_config_root_defaults_and_validation]], config migration in [[tests/test_config_migration.py#test_load_config_keeps_max_tokens_and_ignores_legacy_memory_window]], operator command paths in [[tests/test_commands.py#test_agent_uses_default_config_when_no_workspace_or_config_flags]], and compatibility CLI branding in [[tests/test_eeebot_cli.py#test_eeebot_cli_help_uses_eeebot_branding]].

## Provider and model contracts

Provider interfaces and adapters route model requests and expose model metadata.

[[nanobot/providers/base.py#LLMProvider]] defines generation behavior; [[nanobot/providers/registry.py#find_by_model]] resolves provider identities and [[nanobot/providers/factory.py#_make_provider]] constructs configured adapters. LiteLLM, Azure, custom, OpenAI Codex, and transcription paths have distinct wire/credential requirements; optional provider imports remain lazy. [[nanobot/providers/model_window.py#resolve_context_window]] resolves model capacity; [[nanobot/cli/model_info.py#find_model_info]] presents operator-facing model information. Relevant checks include lazy exports in [[tests/test_providers_init.py#test_importing_providers_package_is_lazy]], adapter imports in [[tests/test_provider_lazy_imports.py#test_openai_codex_provider_import_does_not_load_oauth_cli_kit]], Azure requests in [[tests/test_azure_openai_provider.py#test_chat_success]], cancellation handling in [[tests/test_provider_retry.py#test_chat_with_retry_preserves_cancelled_error]], and model-window lookup in [[tests/test_model_window.py#test_resolve_known_model_returns_max_input_tokens]]. Provider-specific assertions beyond these anchors are not claimed.

## Scheduling, heartbeat, telemetry, and safety

Chat services schedule agent work, record model calls, and apply network safety checks.

[[nanobot/cron/service.py#CronService]] manages scheduled jobs described by [[nanobot/cron/types.py#CronJob]]; [[nanobot/heartbeat/service.py#HeartbeatService]] provides periodic agent work. These are chat-framework services, not the separate host runtime scheduler. [[nanobot/observability/llm_telemetry.py#record_llm_call]] records model-call observations with redaction/retention constraints. [[nanobot/security/network.py#validate_url_target]] and [[nanobot/security/network.py#validate_resolved_url]] enforce network-target checks also relevant to tool adapters. [[nanobot/agent/tools/web_transport.py#PinnedAddressTransport]] pins web_fetch connections to validated per-hop DNS snapshots while preserving origin Host/SNI/certificate verification; redirects are validated before the next request, and proxy/Jina-fetch paths fail closed or are disabled. [[tests/test_web_fetch_security.py#test_transport_pins_address_and_preserves_origin]] covers the actual transport adapter with deterministic TCP/TLS fixtures. [[tests/test_web_fetch_security.py#test_transport_closes_pool_on_response_read_error]] verifies pool closure after a transport read failure when the response is closed; [[tests/test_web_fetch_security.py#test_web_fetch_closes_response_when_read_is_cancelled]] and [[tests/test_web_fetch_security.py#test_web_fetch_closes_response_when_close_is_cancelled]] verify response cleanup is retried after read/close cancellation; [[tests/test_web_fetch_security.py#test_pool_stream_attempts_pool_close_after_stream_close_cancellation]] and [[tests/test_web_fetch_security.py#test_pool_stream_closes_pool_when_stream_close_fails]] verify pool close is attempted after stream close raises. [[tests/test_web_fetch_security.py#test_web_fetch_returns_error_when_response_close_fails]] asserts close errors return JSON errors. Cleanup completion is not guaranteed when cleanup itself fails or cancellation recurs. [[tests/test_web_fetch_security.py#test_web_fetch_redirect_close_error_stops_before_next_hop]], [[tests/test_web_fetch_security.py#test_web_fetch_redirect_close_cancellation_retries_cleanup_without_following]], [[tests/test_web_fetch_security.py#test_web_fetch_does_not_advance_after_redirect_limit_close_failure]], and [[tests/test_web_fetch_security.py#test_web_fetch_does_not_advance_after_missing_location_close_failure]] cover redirect close failures/cancellation and ensure a failed close does not advance to another request. [[tests/test_web_fetch_security.py#test_web_fetch_redirect_close_pool_cleanup_reaches_actual_transport]] and [[tests/test_web_fetch_security.py#test_web_fetch_redirect_close_pool_cancellation_reaches_actual_transport]] exercise the actual adapter and verify the redirect pool has no remaining connections. [[tests/test_web_fetch_security.py#test_web_fetch_carries_same_origin_cookie_to_redirect]] covers same-origin cookie retention across per-hop clients, [[tests/test_web_fetch_security.py#test_web_fetch_does_not_leak_cookies_across_redirects]] covers cross-origin non-leakage, and [[tests/test_web_fetch_security.py#test_web_fetch_cookie_jar_preserves_domain_path_and_secure_scope]] checks HTTPX cookie domain/path/secure scope. [[tests/test_web_fetch_security.py#test_web_fetch_decodes_declared_charset]] checks non-UTF-8 response decoding. [[tests/test_web_fetch_security.py#test_web_fetch_removes_expired_cookie_before_next_redirect]] checks expiry synchronization with copied HTTPX client jars, and [[tests/test_web_fetch_security.py#test_pinned_backend_shares_timeout_budget_across_addresses]] plus [[tests/test_web_fetch_security.py#test_pinned_backend_fails_over_with_remaining_timeout]] check a shared per-connection address-attempt timeout budget. [[tests/test_web_fetch_security.py#test_web_fetch_does_not_call_jina_fetch]] asserts the fetch tool does not invoke its Jina helper. Existing checks include cron timezone validation in [[tests/test_cron_service.py#test_add_job_accepts_valid_timezone]], heartbeat skip behavior in [[tests/test_heartbeat_service.py#test_decide_returns_skip_when_no_tool_call]], call recording in [[tests/test_llm_telemetry.py#test_record_llm_call_writes_well_formed_line]], and private-address rejection in [[tests/test_security_network.py#test_blocks_private_ipv4]].

## Supporting contracts

Shared helpers, evaluation, process attribution, and package assets support framework services.

[[nanobot/utils/helpers.py#split_message]] and [[nanobot/utils/helpers.py#sync_workspace_templates]] provide shared formatting/workspace utilities; [[nanobot/utils/evaluator.py#evaluate_response]] evaluates responses. [[nanobot/crash_record.py#record_exit]] records process outcomes. Package initializers and [[nanobot/__main__.py]] expose package/launch surfaces; template initializers and skill scripts are distribution assets, not independent services. Existing checks include token fallback in [[tests/test_helpers_tiktoken_fallback.py#test_estimate_prompt_tokens_falls_back_without_tiktoken]], response evaluation fallback in [[tests/test_evaluator.py#test_fallback_on_error]], process attribution in [[tests/test_attribution.py#test_own_process_attribution_uses_proc_self_never_hostwide_aggregates]], and import naming in [[tests/test_import_hygiene.py#test_no_internal_eeebot_imports]]. Crash-record details and template package markers have no specific test assertion established here.

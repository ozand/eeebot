# ERR-2026-06-14-001: Deployed Release missing SOURCE_COMMIT metadata

## Symptom
The self-evolving agent loop went idle, and subagents stopped receiving tasks.
The coordinator logs in `eeepc-self-evolving-agent-health.service` reported a block at the promotion stage (`blocked_not_ready` state).

## Root Cause
The coordinator promotion module evaluates candidates by comparing them to the active release. It resolves the active version by reading a `SOURCE_COMMIT` file in the release root. If this file is missing, the promotion engine cannot determine the base git hash, stalling candidate verification to prevent unverified code deployment.

## Fix Applied
1. Resolved the active release commit hash via git log.
2. Manually wrote the hash to the `SOURCE_COMMIT` file inside the active release directory:
   ```bash
   echo "3b056385db49b1ff1461ff399e4b789a5839ceb8" > /opt/eeepc-agent/runtimes/self-evolving-agent/releases/20260609T203743Z-canonical-3b05638/SOURCE_COMMIT
   ```
3. Restarted the health service to trigger verification:
   ```bash
   sudo systemctl start eeepc-self-evolving-agent-health.service
   ```
4. Approved the candidate promotion once verified.

## Prevention
Every packaging script, deployment recipe, or manual hotfix setup must preserve and write the `SOURCE_COMMIT` file containing the exact git hash of the codebase inside the active release root directory.

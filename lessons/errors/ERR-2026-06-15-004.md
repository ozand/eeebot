# ERR-2026-06-15-004: Direct SCP Permission Denied on opencode-owned subagent repository files

## Metadata
* **ID**: ERR-2026-06-15-004
* **Date**: 2026-06-15
* **Category**: workspace-permissions
* **Title**: Direct SCP Permission Denied on opencode-owned subagent repository files

## Description
Attempting to copy code files directly from the subagent research workspace `/home/opencode/servers_team/repo_research/` via `scp` under the default user account (`ozand`) failed with `Permission Denied` or `No such file or directory`.

## Root Cause
The files and directories within the subagent repository are owned by the system user `opencode` and group-writable (e.g. group `eeepc-agent`), but the SSH session runs under the normal operator account `ozand`, which does not have read permissions to parts of the home directory structure of `/home/opencode/`. Direct `scp` requests run with `ozand`'s privileges and are therefore blocked by standard Linux DAC (Discretionary Access Control) permissions.

## Impact
Unable to directly pull down agent-materialized improvements or runtime logs from the host workspace, slowing down verification, debugging, and porting of fixes.

## Fix Applied
Used SSH command substitution with sudo to read files:
```bash
ssh eeepc "sudo -u opencode cat /path/to/file" > local_file
```
This bypasses the SCP limitation by executing the read step as `opencode` on the host side, then piping stdout over the secure tunnel back to the local system.

## Prevention
Always access research repository files on the host using `sudo -u opencode` commands instead of direct `scp` under normal user accounts. Keep this in mind when implementing automated sync tools or runbooks.

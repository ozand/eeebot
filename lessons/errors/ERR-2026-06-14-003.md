# ERR-2026-06-14-003: Timer Stagnation due to OnUnitActiveSec and NTP Clock Adjustment

## Symptom
The periodically triggered systemd timer stopped executing the subagent bridge, leaving the timer status in 'waiting' state but with a dead trigger date ('Trigger: n/a').

## Root Cause
The timer relied on OnUnitActiveSec=10m. Clock drift adjustments by NTP synchronization and hardware CPU constraints on Eee PC caused the systemd relative scheduler to lose unit activation markers.

## Fix Applied
1. Manually restarted the timer unit to reschedule the bridge.
2. Upgraded systemd timer templates to use OnUnitInactiveSec or calendar-based interval patterns.

## Prevention
Do not use OnUnitActiveSec for critical system daemons on clock-drifting devices. Prefer OnUnitInactiveSec.

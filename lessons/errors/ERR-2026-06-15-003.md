# ERR-2026-06-15-003: Subagent-Coordinator Desync due to Missing Execution Timeouts

## Symptom
Subagents ran up to 87 minutes, bypassing the coordinator's stale threshold of 1 hour. The coordinator assumed the subagent had hung or died, proceeded to write stale results, and spawned parallel subagents. This led to multiple subagents concurrently accessing the same repository and wasting LLM tokens.

## Root cause
1. Subagents are bound only by a 15-iteration limit (`max_iterations = 15`), which has no physical wall-clock protection.
2. Latency of LLM requests or slow execution on the Eee PC hardware allowed 15 iterations to take longer than 60 minutes.
3. No timeout limits were defined at the subagent bridge level (`scripts/eeepc_self_evolving_subagent_bridge.py`) or the systemd service unit.

## Fix
1. Wrapped the subagent execution in `asyncio.wait_for` with a `3000.0`s (50 minutes) timeout in `eeepc_self_evolving_subagent_bridge.py` so the bridge terminates execution and writes a `"cancelled"` state to the database.
2. Added a systemd service override `95-runtime-timeout.conf` setting `RuntimeMaxSec=3300` (55 minutes) to guarantee physical termination of hung processes.

## Prevention
- Always ensure runtime/bridge timeouts are strictly lower than the coordinator's stagnation thresholds (e.g., 50m bridge limit vs 1h coordinator threshold).
- Define physical timeouts (`RuntimeMaxSec`) for all systemd-scheduled tasks executing LLM workflows.

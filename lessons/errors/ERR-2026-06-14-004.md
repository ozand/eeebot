# ERR-2026-06-14-004: Critical Queue Pressure Warning due to Unpruned Results Directory

## Symptom
The system health status turned to CRIT due to queue pressure (443 pending / 25 stale). However, the cleanup scripts were reporting 0 stale requests archived.

## Root Cause
1. Dashboard parsed the entire 'subagents/' directory recursively using rglob("*") to compute pressure.
2. Cleanup scripts only walked 'subagents/requests/', leaving files in 'subagents/results/' and temporary root logs unpruned.
3. Old request payloads lacked a 'timestamp' JSON key and were skipped by initial regex parsers.

## Fix Applied
1. Extended cleanup_subagent_queue.py to target requests/, results/, and root json files.
2. Swapped cleanup logic to use filesystem mtime as a fallback when JSON timestamps are missing.
3. Added a systemd hourly timer pointing to the updated cleanup tool.

## Prevention
Pruning routines and dashboard monitoring logic must cover identical scopes.

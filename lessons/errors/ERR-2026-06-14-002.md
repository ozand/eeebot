# ERR-2026-06-14-002: Git Database Commit Failures due to Multi-User Object Ownership Conflict

## Symptom
Subagents completed their tasks successfully in logs but failed to create commits.
Executing git commands on the target workspace returned 'insufficient permission for adding an object to repository database'.

## Root Cause
When git commands are run by different users (specifically `root` or `opencode`), new Git object directories and packfiles are created under `.git/objects/` with that user's default ownership and `umask`.
If a subsequent git command run by `eeepc-agent` needs to write to a directory owned by `root` (e.g. `.git/objects/07/`), it fails due to lack of write permission.

## Fix Applied
1. Changed workspace repository owner to opencode:eeepc-agent:
   ```bash
   sudo chown -R opencode:eeepc-agent /home/opencode/servers_team/repo_research/eeebot-self-evolving
   ```
2. Reset database permissions recursively via chmod g+rw:
   ```bash
   sudo chmod -R g+rw /home/opencode/servers_team/repo_research/eeebot-self-evolving
   ```
3. Configured `core.sharedRepository` to respect shared access permissions by default:
   ```bash
   git -C /home/opencode/servers_team/repo_research/eeebot-self-evolving config core.sharedRepository group
   ```

## Prevention
Never run git commit or modify workspace files as root. Keep `core.sharedRepository group` active.
